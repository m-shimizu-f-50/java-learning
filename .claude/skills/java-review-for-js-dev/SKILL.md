# Java演習コードレビュー（JS経験者向け）

## 前提

レビュー対象はJavaScript経験者がJavaを学習中に書いた演習コード。「知らない概念」ではなく「JSの感覚のまま書いてしまっている箇所」を優先的に指摘する。

## チェック観点（優先度順）

1. **型の扱い**: プリミティブ型とラッパークラス（int/Integer等）の使い分け、不要なキャスト、JSの緩い型変換の感覚が残っていないか
2. **null安全性**: nullチェック漏れ、Optionalを使うべき箇所で素のnullを返していないか
3. **アクセス修飾子**: private/public/protectedの使い分け。JSにはない概念なので、フィールドを安易にpublicにしていないか（カプセル化）
4. **クラス設計**: コンストラクタの書き方、`this`の使い方、フィールド初期化のタイミング
5. **継承・ポリモーフィズム**: `extends`/`super`/`@Override`の使い方。JSのprototype継承と違い、Javaは型として親子関係を持つ点を意識できているか
6. **インターフェース**: `implements`の使い方。JSにはない概念なので、なぜインターフェースを使うのかを理解しているかを見る
7. **命名規則**: クラス名はPascalCase、メソッド/変数はcamelCase、定数はUPPER_SNAKE_CASE。JSの命名習慣が混ざっていないか
8. **例外処理**: try-catchの使い方、checked/unchecked exceptionの違い（JSには無い区別）
9. （進捗が進んだら）**Stream API・ラムダ式**: JSの`map`/`filter`との対応関係を踏まえた使い方ができているか

## フィードバックの出し方

CLAUDE.mdの「説明→演習→フィードバックのサイクル」「理解度を確認しながら進める」という方針に沿って、以下の順で返す。

1. 良い点を先に1〜2個挙げる
2. JSの感覚のまま書いている箇所を指摘し、「JSではこう書くが、Javaではこう考える」という対比で説明する
3. 改善コード例を示す
4. 理解度を確認する質問を1つ添えて終える（次の演習にそのまま進めるかの判断材料にする）
