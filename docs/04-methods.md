# 04. メソッド

## 用語集

- **オーバーロード**: 同じ名前で、引数の型・数が異なる複数のメソッドを1つのクラスに定義すること
- **エントリーポイント**: プログラムの実行が最初に始まる場所。Javaでは`main`メソッドがこれにあたる
- **JVM（Java Virtual Machine）**: コンパイルされたJavaのコード（バイトコード）を実行する仮想マシン。OSの違いを吸収し、どの環境でも同じJavaコードを動かせるようにする
- **シグネチャ**: メソッド名と引数の型・数の組み合わせのこと。オーバーロードはこのシグネチャの違いで区別される

## 使い方

### 基本構文

```java
戻り値の型 メソッド名(引数の型 引数名, ...) {
    ...
    return 戻り値;
}
```

戻り値がない場合は `void` を使う。

### オーバーロード

Javaは同名・引数違いのメソッドを複数定義できる（JSにはない概念）。「シグネチャ（メソッド名＋引数の型・数）」が違えば、別々のメソッドとして共存できる。

### オーバーロードの解決順序：どの定義が呼ばれるか

```java
static void show(int x) { System.out.println("int版: " + x); }
static void show(double x) { System.out.println("double版: " + x); }

show(5);   // int版（ぴったり一致）
show(5.0); // double版（ぴったり一致）
```

Javaは引数の型を見て、以下の順序で呼び出すメソッドを決める。

1. **ぴったり一致するものを優先**：`show(5)`なら`int`版がそのまま一致するのでそちらが呼ばれる
2. **一致するものが無ければ、安全な変換（widening、情報が失われない変換）だけを試す**：`int`→`double`、`int`→`long`など。`show(double x)`しか定義されていない状態で`show(5)`（`int`）を呼ぶと、`5`が自動で`5.0`に変換されて呼ばれる
3. **情報が失われる可能性のある危険な変換（narrowing）は自動的に行われない**：`show(int x)`しか定義されていない状態で`show(5.0)`（`double`）を呼ぶと、コンパイルエラーになる（`double`→`int`は明示的な`(int)`キャストが必要）

```java
// int版のみ定義されている場合
show(5.0); // コンパイルエラー: 精度が失われる可能性があるdoubleからintへの変換

// double版のみ定義されている場合
show(5);   // OK: intが自動的にdoubleへ変換される（widening）
```

### オーバーロードとオーバーライドの違い

似た名前で混同しやすいが、全く別の仕組み。

| | オーバーロード（Overload） | オーバーライド（Override） |
|---|---|---|
| 関係 | 同じクラス内 | 親クラスと子クラス（継承関係、[06. 継承](06-inheritance.md)） |
| メソッド名 | 同じ | 同じ |
| 引数（シグネチャ） | **違う**（型や数が異なる） | **同じ**（完全に一致） |
| 決まるタイミング | コンパイル時（引数の型で決まる） | 実行時（動的ディスパッチ、[07. インターフェース](07-interface.md)のポリモーフィズム） |
| 目印 | 特になし | `@Override`を付ける（`06-inheritance`の慣習） |

一番の見分け方は「引数（シグネチャ）が同じか違うか」。同じなら親子関係でのオーバーライド、違うなら同じクラス内でのオーバーロード。

### 別クラスのstaticメソッドを呼ぶには、クラス名を付ける

```java
// CalcDiscountクラスに定義されたstaticメソッドをMainから呼ぶ場合
CalcDiscount.calcDiscount(2000, 30); // OK: クラス名.メソッド名
calcDiscount(2000, 30);              // エラー: シンボルを見つけられません
```

`12-static`で確認した「クラス名.メソッド名」の呼び出し方は、別クラスのstaticメソッドを呼ぶときにも同様に必要。メソッド名だけを書くと、コンパイラは「同じクラス内にあるはず」と探しにいき、見つからずエラーになる。

### static

`main`から直接呼ぶメソッドは今の段階では `static` をつける（詳細はオブジェクト指向で扱う）。

### エントリーポイント

```java
public static void main(String[] args) {
    ...
}
```

これはJVMがプログラムのエントリーポイントとして認識するための決まったシグネチャ。定型文として覚えてよい。

## 覚えておくべきルール・規約

- 戻り値がない場合は`void`を指定する
- 同名でも引数が違えば複数定義できる（オーバーロード）
- オーバーロード解決は「①ぴったり一致→②安全な変換（widening）のみ自動で試す→③危険な変換（narrowing）は自動的に行われずコンパイルエラー」の順
- オーバーロード（同クラス内・シグネチャが違う・コンパイル時に決まる）とオーバーライド（親子関係・シグネチャが同じ・実行時に決まる）は別の仕組み
- 別クラスのstaticメソッドを呼ぶときは`クラス名.メソッド名(...)`が必要
- 戻り値の型は、`return`する式の型と一致させる（`double`の計算結果を`int`の戻り値として返そうとするとコンパイルエラー）
- `main`から直接呼ぶメソッドには`static`をつける
- `public static void main(String[] args)`はJVMが認識する決まったシグネチャで変更不可

### 復習（`review/28-methods`）：オーバーロードの実装で発生した3つのミス

**何が起きたか**: 割引計算をオーバーロードで実装する際、以下が連鎖的に発生した。

1. `Main`から`CalcDiscount(2000, 30)`と呼び出し、「シンボルを見つけられません」エラー。実際のメソッド名は`calcDIscount`（タイプミス）で、かつ別クラスのstaticメソッドなのに`CalcDiscount.`というクラス名の修飾が付いていなかった
2. `calcDiscount(double price, double rate)`の戻り値の型を`int`と宣言したまま、`double`の計算結果（`price - price * rate`）を`return`しようとしてコンパイルエラー
3. （解消済みの前提として）メソッド名の大文字小文字のタイプミス（`calcDIscount` → `calcDiscount`）

**なぜ**: 1は`12-static`で学んだ「別クラスのstaticメソッドはクラス名.メソッド名で呼ぶ」というルールを見落としていた。2は`double`版のオーバーロードを書く際、戻り値の型を`int`版からコピーしたまま変更し忘れていた。

**教訓**: オーバーロードで複数の型のバリエーションを書くときは、引数の型だけでなく**戻り値の型も含めて型を揃える**必要がある。片方をコピーして作るときは、戻り値の型の書き換え漏れに注意する。

演習コードは `review/28-methods/CalcDiscount.java`, `Main.java`。コンパイル・実行して動作確認済み（整数の割引率：1400、小数の割引率：1000.0）。2つ目の呼び出し`calcDiscount(2000, 0.5)`では、`int`の`2000`が自動的に`double`へ変換されて`double`版が呼ばれることも確認した。
