# 03. 配列

## 用語集

- **固定長**: 一度作成したら要素数を後から変更できない性質。配列はこの性質を持つ
- **多次元配列**: 配列の中にさらに配列が入っている構造（`int[][]`など）。表（行と列）のようなデータを表せる
- **length**: 配列の要素数を表すプロパティ。メソッドではないので`()`は不要（`array.length`）

## 使い方

### 配列の宣言

```java
int[] scores = {80, 65, 90, 72, 55};
```

配列は固定長で、JSの `push` のようにサイズを後から変えることはできない。また同じ型の要素しか入れられない。

### 走査

```java
for (int n : scores) {
    // 拡張for文で全要素を走査
}
```

`scores.length` は配列の長さを持つプロパティ（メソッドではないので `()` 不要）。

### 多次元配列

```java
int[][] table = {{1, 2}, {3, 4}};
table[1][0]; // 3
```

### 範囲外のインデックスは「実行時」にエラーになる

```java
int[] temps = {22, 25, 19, 30};
System.out.println(temps[4]); // コンパイルは通る。実行時にArrayIndexOutOfBoundsException
```

インデックスは`0`から始まるので、要素数4の配列で有効なのは`0`〜`3`。`temps[4]`はコンパイルは通り、**実行時**に`ArrayIndexOutOfBoundsException`が発生する。`if (stock)`（`int`を`boolean`として使う）のような「型の食い違い」はコンパイル時に分かるが、インデックスが範囲内かどうかは「配列の要素数」「インデックスの値（`for`の変数やユーザー入力のこともある）」という**実行時の値**に依存するため、コンパイラは基本的に検出しない。

### 配列は参照型：代入は「実体の共有」になる

```java
int[] a = {1, 2, 3};
int[] b = a;      // 中身のコピーではなく、同じ実体への参照のコピー
b[0] = 99;
System.out.println(a[0]); // 99（aとbは同じ実体を指している）
```

配列は参照型（[01. 変数と型](01-variables-types.md)）なので、`int[] b = a;`は中身のコピーではなく**同じ実体を2つの名前で指す**だけ。片方を書き換えるともう片方にも反映される。独立したコピーが欲しい場合は`Arrays.copyOf`を使う。

```java
int[] independent = Arrays.copyOf(original, original.length); // 値をコピーした別の実体
independent[0] = 0; // originalは変わらない
```

### 平均を求めるときの整数除算

```java
double average = (double) sum / steps.length; // sumをdoubleにキャストしてから割る
```

`int`同士の割り算は小数点以下が切り捨てられる（整数除算）。`sum / steps.length`のままだと、割り切れない場合に小数が消えてしまう。先に`(double)`でキャストしてから割る。

### 可変長が必要な場合

サイズが変わる配列が必要な場合は `ArrayList` を使う（[08. コレクション](08-collections.md)）。

## 覚えておくべきルール・規約

- 配列は固定長。生成後にサイズを変更できない
- 配列には同じ型の要素しか入れられない
- `array.length`はプロパティ（`()`をつけない）
- インデックスは`0`始まり。範囲外はコンパイルは通り、実行時に`ArrayIndexOutOfBoundsException`になる
- 配列は参照型。`b = a`は実体を共有するだけ（片方の書き換えがもう片方に反映される）。独立したコピーは`Arrays.copyOf`で作る
- 可変長が必要なら`ArrayList`を使う

## つまずきの分析

今回は目立ったつまずきなし。整数除算を避けるための `(double)` キャストも正しく使えていた。

### 復習（`review/27-arrays`）：範囲外アクセスをコンパイルエラーと予想

**何が起きたか**: `temps[4]`（要素数4の配列）について「コンパイルエラーになる」と予想したが、実際はコンパイルが通り、実行時に`ArrayIndexOutOfBoundsException`が発生した。「インデックスは0から始まるので4番目はない」という理由づけ自体は正しかった。

**なぜ**: 「エラーになる理由」は分かっていたが、「エラーがいつ検出されるか（コンパイル時か実行時か）」を区別できていなかった。`02`の`if (stock)`が型の食い違いでコンパイル時に検出されるのと同じ感覚で考えてしまった。

**教訓**: コンパイラが検出できるのは主に**型**の問題。値に依存する問題（範囲外インデックス、`null`参照など）は実行時に検出される。「エラーになる」だけでなく「いつ・どの段階で」を意識する。

演習コードは `review/27-arrays/Main.java`。コンパイル・実行して動作確認済み（最大値10300、合計41500、平均8300.0、代入後のsteps[0]=0、copyOf後のoriginal[0]=8200、対角成分の合計15）。なお、平均・コピー・対角成分の実装部分は演習者の依頼により実装を補助した。
