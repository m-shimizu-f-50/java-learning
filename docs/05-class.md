# 05. クラスとオブジェクト

## 用語集

- **インスタンス**: クラスという設計図から`new`で実際に作られた実体（オブジェクト）
- **コンストラクタ**: `new`でインスタンスを作るときに自動的に呼ばれる、初期化専用の特別なメソッド。クラス名と同名で、戻り値の型を書かない
- **this**: そのメソッドを呼び出したインスタンス自身を指すキーワード

## 使い方

### インスタンス生成

```java
Book book = new Book("Java入門", 2500);
```

`new クラス名(...)` でインスタンスを生成する。JSの `new` と同じ感覚。

### コンストラクタ

クラス名と同名で、戻り値の型は書かない。インスタンス生成時に自動で呼ばれる。

### this

インスタンス自身を指す。JSの `this` と近い感覚だが、挙動はより単純（呼び出し方によって指すものが変わることはない）。

### ファイル構成

データを表すクラス（`Book`）と実行の入口（`Main`）は別ファイルに分けるのが一般的。

### 複数ファイルのコンパイル

```bash
javac Book.java Main.java
```

## 覚えておくべきルール・規約

- 1ファイルに`public`クラスは1つまで、ファイル名と一致させる
- コンストラクタはクラス名と同名、戻り値の型は書かない
- データを表すクラスと実行の入口（Main）は別ファイルに分けるのが一般的
- 複数ファイルは`javac A.java B.java`のようにまとめてコンパイルできる

## つまずきの分析

### 1ファイルに複数publicクラス

**何が起きたか**: `Book.java` に `public class Book` と `public class Main` の両方を書いてしまい、「The public type Main must be defined in its own file」エラーが発生した。

**なぜ**: Javaは1ファイルにつき `public` クラスを1つまでしか許可しない仕様のため。

**教訓**: `Main.java` に分離することで解決。データを表すクラスと実行の入口は最初から別ファイルに分ける習慣をつける。

### エディタ上の表示エラー

**何が起きたか**: ファイル分離後、VSCode上で「Book cannot be resolved to a type」という表示エラーが出た。

**なぜ**: 実際に `javac` でコンパイルすると成功しており、原因はコンパイルエラーではなく、言語サーバーが新規ファイルをまだ認識していなかっただけの表示上の問題だった。

**教訓**: エディタ上のエラー表示とコンパイル結果が食い違う場合は、まず実際にコンパイルして確かめる。表示側の問題であれば `Java: Clean Java Language Server Workspace` やウィンドウリロードで解消できる。
