# 02. 制御構文

## 用語集

- **拡張for文**: 配列やコレクションの全要素を順に取り出す構文（`for (型 変数 : 対象)`）。JSの`for...of`に相当
- **矢印構文**: Java 14以降の`switch`で使える`->`を使った書き方。`break`を書かなくても次のcaseに流れ落ちない
- **boolean（真偽値）**: `true`か`false`のどちらかしか取らない型。`if`の条件式は必ずこの型でなければならない

## 使い方

### if文

```java
if (score >= 90) {
    // ...
} else if (score >= 70) {
    // ...
} else {
    // ...
}
```

条件式は必ず `boolean` 型でなければならない。JSのように数値や文字列を暗黙的に真偽判定することはできない。

```java
int stock = 0;
if (stock) { ... } // コンパイルエラー: intをbooleanに変換できません
```

JSでは`0`はfalsyとして扱われるが、Javaでは`int`をそのまま条件式に書くとコンパイルエラーになる。比較したい場合は`stock == 0`のように`boolean`を返す式を書く必要がある。

この厳格さには実務上のメリットもある。`if (stock = 0)`（`==`のつもりで`=`と書くタイプミス）も、Javaでは代入結果（`int`）が`boolean`ではないためコンパイルエラーになる。C言語などでは同じミスが実行時まで検出されずバグの温床になるが、Javaの「条件式は`boolean`必須」というルールがこれを防いでくれる。

### for文

```java
for (int i = 1; i <= 10; i++) {
    // ...
}

// 拡張for文（JSのfor...of相当）
for (int n : nums) {
    // ...
}
```

通常のfor文はJSと同じ書き方に加えて、配列やコレクションの全要素を走査する拡張for文が使える。

### while / do-while

JSと同じ書き方。

### switch文

```java
switch (day) {
    case 1 -> System.out.println("月曜");
    default -> System.out.println("不明");
}
```

Java 14以降の矢印構文を使うと `break` が不要になる。

### 従来のswitch文とフォールスルー（矢印構文を使う理由）

矢印構文ではなく`:`を使う従来の書き方では、`break`を書き忘れると、マッチした`case`から**次の`case`にそのまま処理が流れ落ちる**（フォールスルー）。

```java
int day = 1;
switch (day) {
    case 1:
        System.out.println("月曜");
    case 2:                          // breakが無いのでここも実行される
        System.out.println("火曜");
    default:                         // ここも実行される
        System.out.println("不明");
}
// 出力: 月曜 / 火曜 / 不明 の3行すべてが実行される
```

矢印構文はこの事故が構造的に起こらない（マッチした`case`のブロックだけが実行される）ため、`break`を書かなくていい、というだけでなく**フォールスルーそのものを防げる**という安全上のメリットがある。これが本教材で最初から矢印構文を採用している理由。

### 1つのcaseに複数の値をまとめる：`,`であって`|`ではない

矢印構文で複数の値を1つの`case`にまとめたいとき、`|`（ビット単位OR演算子）ではなく**カンマ（`,`）**を使う。

```java
case 12, 1, 2 -> System.out.println("冬");  // 正しい: 12, 1, 2のいずれかにマッチ
case 12 | 1 | 2 -> System.out.println("冬"); // 誤り: ビット単位ORとして計算されてしまう
```

`|`を使うと「複数の値のどれか」ではなく、**ビット単位ORの計算結果という1つの値**になってしまう。偶然別の`case`の計算結果と同じ値になると「caseラベルが重複しています」というコンパイルエラーになる（例: `12 | 1 | 2`と`6 | 7 | 8 | 9`はどちらも`15`になり衝突する）。

## 覚えておくべきルール・規約

- `if`の条件式は必ず`boolean`型（数値やオブジェクトの暗黙的な真偽判定はできない）。`==`のつもりで`=`と書くタイプミスも、この制約のおかげでコンパイルエラーとして検出される
- `switch`の矢印構文（`case X -> ...`）を使うと`break`が不要になるだけでなく、フォールスルー自体が起こらない
- 従来の`:`を使う`switch`は`break`を忘れるとフォールスルー（次のcaseに処理が流れ落ちる）が起きる
- 1つの`case`に複数の値をまとめるときは`,`を使う。`|`はビット単位OR演算になり別の意味になってしまう
- 想定外の値に備えて`default`ケースを入れておくのが実務での安全策

### 復習（`review/26-control-flow`）：switchで`|`と`,`を混同

**何が起きたか**: 矢印構文で複数の値を1つの`case`にまとめる際、`case 12 | 1 | 2 -> ...`のように`|`を使い、「caseラベルが重複しています」というコンパイルエラーになった。

**なぜ**: `|`がビット単位OR演算子であることを踏まえず、「複数の値を並べる記号」として使ってしまった。`12 | 1 | 2`と`6 | 7 | 8 | 9`が偶然どちらも`15`という同じ計算結果になり、コンパイラには「同じ値のcaseが2つある」ように見えてしまった。

**教訓**: 複数の値を1つの`case`にまとめるときは`,`（カンマ）。`|`は別の演算子（ビット単位OR）であり、意味が全く異なる。
