# 16. 可変長引数（varargs）

## 用語集

- **可変長引数（varargs）**: 呼び出し時に個数を指定せず、複数の値を渡せる引数（`型... 変数名`）。メソッド内では配列として扱われる

## 使い方

### 基本構文

```java
static int sum(int... numbers) { // int[]の代わりに int... と書く
    int total = 0;
    for (int n : numbers) {
        total += n;
    }
    return total;
}
```

```java
sum();              // 0個 → 0
sum(1, 2, 3);        // 3個 → 6
```

メソッド内では`numbers`は実質`int[]`として扱われる。JSのレストパラメータ（`function sum(...numbers)`）に近い発想。

### なぜ使うか：呼び出し側の記述がシンプルになる

可変長引数を使わず配列引数（`int[] numbers`）にすると、呼び出し側は明示的に配列を組み立てる必要がある。

```java
sum(new int[]{1, 2, 3}); // 配列引数の場合：{}で配列を組み立てる必要がある
sum(1, 2, 3);            // 可変長引数の場合：値を並べるだけでいい
```

「0個以上の同じ型の値を受け取りたい、かつ呼び出し側の書き方をシンプルにしたい」という場面で使う。

### 何も渡さなくてもnullにはならない

```java
static void printNumbers(int... numbers) {
    System.out.println(numbers.length); // 何も渡さなくてもエラーにならない
}
printNumbers(); // 要素数: 0
```

`11-encapsulation`で「未初期化の参照型フィールドは`null`」と確認したが、可変長引数は別の規則で動く。引数を1つも渡さなかった場合、`numbers`は`null`ではなく**要素数0の配列（空配列）**になる。もし`null`だったら`numbers.length`で`NullPointerException`になるはずだが、そうならない。

これにより、呼び出し側が何個渡したか・渡さなかったかを気にせず、**`null`チェックなしで安全に`.length`や拡張for文を使える**。可変長引数は「配列だが、`null`になる心配をしなくていい特別な配列」という扱い。

### 配列を直接渡すこともできる

```java
int[] arr = {1, 2, 3};
sum(arr);
```

### 固定引数との組み合わせ

```java
void printScores(String name, int... scores) { ... }
```

可変長引数は引数リストの**最後に1つだけ**書ける。

## 覚えておくべきルール・規約

- `型... 変数名`で宣言し、メソッド内では配列として扱われる
- 可変長引数は引数リストの最後に1つだけ許される
- 固定引数と可変長引数を組み合わせられる（固定引数が先、可変長引数が最後）
- `sum(int a, int b)`と`sum(int... numbers)`が両方あれば、より具体的にマッチする固定引数版が優先される
- 可変長引数は、何も渡さなくても`null`にはならず要素数0の配列になる。`null`チェックが不要
- メソッドはクラスの直下に並べて書く。他のメソッドの中（`{}`の内側）に別のメソッドを定義することはできない（JSの関数の入れ子とは異なる）

### 復習（`review/40-varargs`）：メソッドをmainの中に入れ子で定義してしまう

**何が起きたか**: `totalPrice`と`printReceipt`という2つのメソッドを、`main`メソッドの`{}`の内側に定義してしまい、「式の開始が不正です」など複数のコンパイルエラーが発生した。`main`の外（クラス直下）に移動することで解決。

**なぜ**: JSでは関数の中に別の関数を定義できる（クロージャなど）が、Javaではメソッドは常にクラスの直下に並べて書くものであり、他のメソッドの中に入れ子にして定義することはできない。

**教訓**: Javaでメソッドを追加する際は、既存の`main`などのメソッドの`{}`の外側（クラスの直下）に書く。「関数の中に関数を書く」というJSの発想を持ち込まないよう注意する。
